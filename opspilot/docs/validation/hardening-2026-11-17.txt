## Docker runtime layout simulation

No Docker daemon is available in this sandbox, so the image was approximated by assembling exactly
the files the `Dockerfile` copies and running the container's commands against them:

```
/tmp/runtime = .next + public + next.config.ts + tsconfig.json + package*.json
             + src/db + src/opspilot/server + opspilot/migrations + opspilot/scripts/migrate.ts
npm ci --omit=dev                                  -> added 56 packages
npx tsx opspilot/scripts/migrate.ts                -> OpsPilot migrations applied successfully.
npx next start -p 3010                             -> Ready in 117 ms
GET /api/health                                    -> {"ok":true}
GET /login                                         -> 200
```

This simulation caught a real regression: adding `src/opspilot/server/config.ts` (imported by
`src/db/index.ts`) broke the migration step because the runtime stage did not copy that directory.
The `Dockerfile` was corrected and the simulation re-run green. The image build itself
(`docker build`) remains unverified — see `PRODUCTION_READINESS.md`.
