## Behaviour probes

```
register (new workspace)                 -> 201, session cookie set, verification email logged
request-reset (known address)            -> 200 {"ok":true,"notice":"If that address has an account, a reset link is on its way."}
request-reset (unknown address)          -> 200 (identical body)   <- no account enumeration
reset with weak password                 -> 400 "Enter a new password of 10–128 characters."
GET /login?mode=reset&token=<64 hex>     -> 200, renders "Choose a new password."
```

## Covered by the test suite (not just manual)

- verification link works once, then 400; `email_verified_at` set
- registration writes exactly one `verify_email` row with status `sent`
- reset revokes existing sessions (old cookie -> 401) and the old password stops working
- invitation: 201 + `workspace_invite` logged; third seat on the free plan -> 402;
  unauthenticated invite -> 401; accept sets role permissions to
  `["customers","invoices","expenses","vendors","documents"]` for `accountant`;
  replayed invitation -> 400; deleted workspace -> 400
- token lifecycle: single use, wrong purpose rejected, expired rejected, rotation retires the old one
